## Task 3: Monitoring and Cost Awareness

This task focuses on basic monitoring, status checks, alerting, cost awareness, and access control for the static website deployed in Task 2.

## 1. Monitoring and Status Checks

The deployed website can be monitored using the following checks:

- Open the live website URL and verify that the website loads correctly.
- Check the GitHub Pages deployment status.
- Check the GitHub repository deployment status.
- Verify that the main webpage loads correctly.
- Verify that the CSS file loads correctly.
- Perform regular availability checks to identify possible downtime.

### Expected Status

The website should be publicly accessible and load successfully through the GitHub Pages URL.

## 2. Simple Alert Idea

A simple availability alert can be used to monitor the website.

If the website becomes unavailable, an alert should notify the administrator.

### Alert Condition

Website is unavailable or does not respond successfully.

### Action

- Check GitHub Pages deployment status.
- Check the repository for recent changes.
- Verify that index.html is available.
- Check whether the website URL is accessible.

## 3. Cost Awareness Checklist

- Monitor hosting costs if applicable.
- Monitor storage usage.
- Monitor bandwidth or network traffic.
- Avoid unnecessary cloud resources.
- Remove unused resources.
- Review service usage regularly.
- Set usage limits or budget alerts where supported.

For this static website, GitHub Pages is used as the hosting platform, keeping the deployment simple with minimal infrastructure.

## 4. Access-Control and Security Checklist

- Keep repository access controlled.
- Use a strong GitHub password.
- Enable two-factor authentication.
- Do not upload passwords, API keys, or secret credentials.
- Give collaborators only the permissions they need.
- Review repository access regularly.
- Keep deployment settings secure.
